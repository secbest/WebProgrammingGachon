E1 · Enable GitHub Pages for webpro-w9

Goal: turn on Pages and confirm the site is live. If you already did this in Monday homework Part A, only verify it.

  1. Open https://github.com/secbest/webpro-w9.
  2. Click Settings, then Pages in the left sidebar.
  3. Under "Build and deployment", set Source to Deploy from a branch.
  4. Branch main, folder / (root), click Save.
  5. Wait about 60 seconds and refresh the page.
  6. Click the live link. Your index.html should appear.
  7. Write down your URL:
https://secbest.github.io/webpro-w9/

Check: the page shows "Hello, Git & GitHub!" with your name. If you see a 404, wait another minute. The repo must be Public.

E2 · Find and understand a 404 page

  1. In a private window, open a page that doesn't exist: 
    https://secbest.github.io/webpro-w9/this-does-not-exist.html
  2. You will see GitHub's generic "404 · File not found" page. Note what it looks like.
  3. Is this a good experience? Answer: No. It is a plain grey GitHub-branded page. It has nothing from your site, it doesn't explain what went wrong, and it gives no obvious way back to your home page. A visitor may think your whole site is broken.
  4. Check your computer: do you have a 404.html in your webpro-w9 folder? Not yet. E3 adds it.

Key fact: GitHub Pages serves a file called 404.html from the repo root whenever a page is missing. Without that file, it shows its generic page.

E3 · Create a custom 404 page

Goal: add a friendly 404 page and deploy it.

The page is ready at webpro-w9/404.html. Copy it into your webpro-w9 folder, next to index.html, then run:

cd C:\Users\Jas\Documents\GitHub\webpro-w9
copy C:\Users\Jas\Documents\GitHub\WebProgrammingGachon\week10\webpro-w9\404.html .
git add 404.html
git commit -m "Add custom 404 page"
git push

Wait about 60 seconds, then open the missing URL from E2 again:

https://secbest.github.io/webpro-w9/nonexistent

Check: you should now see your own "Oops! Page not found" page with a Back to Home button, instead of GitHub's grey page. The button goes to https://secbest.github.io/webpro-w9/.

Two choices I made, so you can explain them:

  • The home link uses the absolute path /webpro-w9/, which breaks the "use relative paths" rule on purpose. A 404 page is shown at whatever missing address was typed, so a relative ./ would point to the wrong folder for a deep address such as /webpro-w9/a/b.
  • The page has a language, a title, a viewport tag, a heading and a visible keyboard focus outline, in line with last week's accessibility lesson. The study guide's sample had none of these.
