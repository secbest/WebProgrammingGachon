Windows PowerShell differences from the study guide. The guide uses Mac/Linux commands. In Windows PowerShell 5.1, two things behave differently:
  • && does not work. Run the two commands on separate lines, or join them with ;.
  • echo "..." > file saves the file as UTF-16, which Git and browsers handle badly. Use the Set-Content form shown below instead.

E1 · Create your first repository

Goal: initialise a repo, create a file, make a first commit. Work outside your course repo, for example in C:\Users\Jas\Documents\GitHub.

mkdir my-first-git
cd my-first-git
git init -b main
Set-Content -Path index.html -Value "<h1>Hello Git</h1>" -Encoding utf8
git status
git add index.html
git commit -m "Initial commit: add index.html"
git log --oneline

What you should see (real output; your hash will differ):

$ git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
        index.html

$ git commit -m "Initial commit: add index.html"
[main (root-commit) d8b0f6b] Initial commit: add index.html
 1 file changed, 1 insertion(+)

$ git log --oneline
d8b0f6b Initial commit: add index.html

Check: git status listed index.html as Untracked before git add, and the log shows one commit.

E2 · Create a branch and merge it

Goal: see files appear and disappear as you switch branches. Stay in my-first-git.

git checkout -b feature-style
Set-Content -Path style.css -Value "body { font-family: sans-serif; }" -Encoding utf8
git add style.css
git commit -m "Add basic stylesheet"
git checkout main
ls
git merge feature-style
ls
git log --oneline --graph --all

What you should see:

$ git checkout -b feature-style
Switched to a new branch 'feature-style'
$ git commit -m "Add basic stylesheet"
[feature-style 969ee47] Add basic stylesheet
$ git checkout main
Switched to branch 'main'
$ ls                      <- style.css is GONE on main
index.html
$ git merge feature-style
Updating d8b0f6b..969ee47
Fast-forward
 style.css | 1 +
$ ls                      <- and now it is back
index.html
style.css
$ git log --oneline --graph --all
* 969ee47 Add basic stylesheet
* d8b0f6b Initial commit: add index.html

Why a straight line and "Fast-forward"? main had no new commits while you worked on the branch, so Git just moved main forward. A fork-and-join graph only appears when both branches change.

E3 · Push your repo to GitHub

Before you start: on github.com click New repository, name it git-exercise, choose Public, and leave "Add a README" unticked. Then, still in my-first-git:

git remote add origin https://github.com/secbest/git-exercise.git
git remote -v
git push -u origin main

What you should see:

$ git remote -v
origin  https://github.com/secbest/git-exercise.git (fetch)
origin  https://github.com/secbest/git-exercise.git (push)
$ git push -u origin main
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.

Check: open https://github.com/secbest/git-exercise. You should see index.html and style.css, and the commit list should show both commits. Only main was pushed; feature-style stays local, which is fine.

How I tested this. I ran E1–E3 for real in a temporary folder, using a local bare repository as a stand-in for GitHub. The output above is from that run, apart from the remote URL. I have not created git-exercise on your GitHub account.
