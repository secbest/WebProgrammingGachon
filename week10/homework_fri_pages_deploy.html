Week 9 Friday Homework · Deploy the Book Search App

Jasper Teo Kheng Cher · K0126002 Web Programming · Repository webpro-book-search

Status: the app is packaged and checked against the deployment checklist. Creating the repo, enabling Pages and submitting need your GitHub login, so those steps are yours. Nothing is live yet.

The 6 steps

  1. Get your Book Search App done The app is the Week 7 lab. A copy named index.html is at webpro-book-search/index.html. It is one self-contained file.
  2. Run the deployment checklist done Results are in the table below.
  3. Create a Public repo named webpro-book-search you On github.com choose New repository, name it exactly webpro-book-search, set Public, and leave "Add a README" unticked.
  4. Push the app you 
    mkdir webpro-book-search && cd webpro-book-search
git init -b main
# copy index.html into this folder, then:
git add .
git commit -m "Deploy Book Search App"
git remote add origin https://github.com/secbest/webpro-book-search.git
git push -u origin main
  5. Enable GitHub Pages you Repo → Settings → Pages → Deploy from a branch → main → / (root) → Save. Wait about a minute, then test https://secbest.github.io/webpro-book-search/ in a private window.
  6. Submit the live URL on the LMS you Paste https://secbest.github.io/webpro-book-search/.

Deployment checklist results

CheckResult
index.html is in the repo rootYes. The file is named index.html at the top level.

Filenames are lowercaseOnly one file, index.html.
No API keys or secretsOpen Library needs no key.
No debug console.logNone. One console.error remains on purpose, to report a failed API retry.
Works on a static hostIt only calls fetch() to the Open Library API from the browser.

Heads up: the Open Library API has had outages. If the live site shows an error, press "Try again" in the app. The app retries and caches results, so this is the service, not your deployment.
